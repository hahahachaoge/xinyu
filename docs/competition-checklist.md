## P0：影响正常使用和数据隔离，优先处理

### 1. 跑通真实向量检索

现场只读查询结果：

| 项目 | 数量 |
| --- | ---: |
| MySQL 知识文档 | 11 |
| MySQL 知识片段 | 40 |
| MySQL 填有 vector_id 的知识片段 | 40 |
| MySQL 标记向量化已完成的文档 | 10 |
| PostgreSQL 实际向量行 | 0 |

数据状态不一致。`AiChatServiceImpl.retrieveChunks` 在向量检索无结果或异常时，会用问题前几个字做模糊匹配。因此，收到 AI 回答或看到来源标签，不能单独证明向量检索有效。

建议：

- 验证嵌入模型 Key、模型、维度和 PostgreSQL 配置，重建向量索引。
- 保持 MySQL 片段与 PostgreSQL 向量的一致性；重建、删除和失败重试都应有明确行为。
- 显示当前检索方式、命中来源和故障状态，避免静默降级让演示结论失真。
- 用至少一组同义表达问题，证明检索不是依赖原文关键词。

验收：上传文档→向量化完成→数据库确有向量→同义提问命中正确文档→来源能回溯。

### 2. 补齐服务端登录、角色和数据归属校验

已确认的代码问题：

- `CurrentUserInterceptor.preHandle` 在无 Token 时设置 userId=0，随后仍返回 true，没有统一限制需要登录的接口。
- `SysUserServiceImpl.signIn` 只在账号、密码非空时添加查询条件，未强制校验必填；数据库有账号时，空凭据可能匹配首个账号。
- `SysUserServiceImpl.register` 使用请求中的用户 DTO 创建账号，没有在服务端固定普通用户角色。
- `AiChatController.getMessages` 和对应服务只按 sessionId 查询，未校验当前用户是否拥有会话；聊天发送也需要补充归属检查。
- 多个后台 CRUD 接口未见管理员校验。前端路由守卫不能替代后端授权。

建议为公开接口建立白名单；其余接口强制登录；后台接口检查管理员角色；用户聊天、测评和收藏等记录必须检查归属。普通用户注册不得接受管理员角色输入。

验收：无登录不能访问受保护数据；普通用户不能调用管理接口；用户 A 无法读取或修改用户 B 的记录；空账号或空密码登录被拒绝。

### 3. 测评应由后端校验并计算

`ScaleTest.vue` 当前在浏览器计算分数和结果，随后提交 userId、totalScore、resultLabel、resultInterpretation；`AssessmentRecordServiceImpl.addOrEdit` 将 DTO 直接映射保存。

建议：客户端提交量表 ID 与答案；后端从登录状态取得用户 ID，验证题目与选项后重新计分。结果、解释和归属不得以客户端提交内容为准。

验收：篡改请求中的分数、结果标签或用户 ID，不能改变最终保存的真实计算结果及归属。

### 4. 补全老师从零部署的路径

现有 README 有基础命令，但缺少完整的首次管理员初始化方法和全新环境验收记录。SQL 已移除账户密码种子，老师不会自动拥有演示管理员账号。

建议：

- 增加首次管理员初始化机制，账号和密码通过本地环境变量或交互输入提供；初始化后不能被公开注册接口提权。
- 补充 PostgreSQL/pgvector 初始化脚本、文档向量化步骤和配置自检。
- 可增加 CMD 启动脚本，检查 Node、Java、Maven、数据库和端口，保留清晰错误提示。
- 从干净目录拉取仓库，按 README 实际完成普通用户、管理员、测评、文章、文档向量化和 AI 问答验证。
- 公开仓库及技术文档不放真实密钥；评审账号也不要使用个人账号或复用个人密码。

## P2：围绕评分提升技术与体验

官方评分：AI 技术深度 35%、创新性 25%、前端工程质量 10%、实用性 10%、用户体验 10%、社会价值与商业潜力 10%。Agent/工作流、多模态、工具集成是细分评分点，不应把所有推荐技术理解为必须全做。

### AI 深度与创新

- 优先完成可验证的 RAG，再准备对照评测：同一组问题比较直接调用模型与 RAG，记录引用正确性、无依据回答情况、首字延迟和失败率。测试问题、参考来源及真实结果均需留档，不能编造指标。
- 可建立 30–50 条带参考文档的评测题，覆盖同义表达、无答案、无关问题、指令注入、API 失败及需要固定求助引导的表达。
- 当前未发现 Agent 工具调用、MCP/Function Calling 或语音交互实现。可选择一个有真实价值的增强方向：受控的“理解需求→检索资料→推荐阅读/练习”工作流，或语音输入与朗读。按实际实现命名，不将固定串行流程描述成自主 Agent。
- 明确作品的独特用户场景，例如考试压力下的可信资料检索、测评后的知识学习路径。通过真实试用反馈证明价值。

### 知识可信度与心理健康场景边界

- 当前 9 个知识 TXT 文件未检出来源链接、作者、发布日期或参考文献标记；`KnowledgeDocument` 未见专门的来源和审核信息字段。补充可核对的原始来源、使用许可、版本及审核记录，避免仅凭“片段来源”暗示内容权威。
- 三套示例量表需补充来源、适用范围、计分依据和使用许可。未经验证的问卷应清楚说明其用途和局限。
- 当前系统提示词有一般性的专业求助建议，但未发现独立的危险表达识别与固定响应流程。建议补充明确的求助入口、人工支持路径和输出边界，并验证其行为。
- 补充聊天和测评数据的用途、保存期限、删除方式及访问范围说明；外部模型接收到哪些信息应向用户解释清楚。

### 前端工程与 AI 交互
